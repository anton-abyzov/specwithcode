# Changelog

## Unreleased

- Messages agents send each other now read as quiet notes instead of large bubbles. On a thread page, the coordinator's message is headed "Message from coordinator", another thread's "Message from <thread>"; on the coordinator page a worker's is headed "Message from <thread>". The text is in muted prose under that header, followed by "View coordinator" or "View thread" and its time, so the person's own messages stay the bubbles on the page. The header is the one fold control: a long message shows its opening until the header opens it, a short one folds to the header, and "Copy original" waits on hover. A thread now also marks where the messages since the last visit begin with a "New" divider.

- Every routine runs in a thread of its own instead of the project's coordinator. Before, a routine without a thread (every routine made in the Routines form, such as "New Relic repair watch") woke the coordinator on each run, and a routine the coordinator scheduled for itself posted into the coordinator's conversation, so watches and reports buried the coordinator's planning. Now a routine's first run starts a thread named after it and later runs continue that thread, keeping the routine's history in one place; a deleted or archived thread is replaced on the next run. Existing routines move on their next run, with nothing to do: one without a thread, or one bound to the coordinator, gets its own thread then. A worker that schedules "wake me when CI finishes" still gets that run in its own thread. Project settings > Routines, the Routines pane and Settings > Routines name each routine's thread ("Own thread" until its first run) and open it, and a routine's results still reach Telegram, headed by the routine's name.

- HTML reports now open in a focused reader from a compact preview, with matching app colors and preserved document state on current Chromium. New report guidance emphasizes readable headings and useful diagrams. Historical pages keep their authored content.

- Automatic fallback no longer discovers unselected ACP agents with unknown billing through same-model matching or the coordinator. Explicit configured choices remain available. Agents cannot claim Copilot subscription identity by advertising its icon.

- The model picker explains the selected harness and protocol and shows reported model billing and capabilities. Pi RPC discovery failures no longer count as ready; OpenCode 2 correctly advertises its existing MCP tools.
- Provider CLI update actions now open an explicit machine selection plan with versions, installer actions, skip reasons and individual results. Verified staged Codex fleet wrappers install through their owning Node/npm beside the current release, verify the executable and switch new sessions atomically. Existing release files and configured paths remain intact. In-place installers refuse while the CLI is in use. Updates use existing provider-management permissions and never restart the app or service.
- A thread moved because its conversation no longer fit a model now sends the request that overflowed again, whole, on the new model. Before, the move sent "Continue where you left off." and the new model saw that request only inside the handed-over history, which keeps at most 16,000 tokens, so a long request such as pasted logs was left out. Subagents that Claude or Codex start on their own are no longer retried or moved, because they take no messages. The **Continuing on** card no longer says the original model has room because the coordinator runs there when a current reading shows it full, and a model with no current usage reading now says so instead of "its last usage reading showed room".
- A thread no longer stops on "Insufficient context allowance for the provider handoff". On October 22 the DCFC thread was sent to Codex GPT-6.1-Sol, whose old session for that thread already held 221,400 of its 258,400 tokens, so the handoff had no room and the run failed in 137 ms. The error promised a compaction and retry that never ran, because the thread was a delegated subagent, and nothing moved it to a model with room. Now a native session too full for the handoff is replaced by a fresh one that gets the thread as a compacted summary. If the conversation still does not fit, or a compaction and retry overflow again, the thread moves to the project's default model when it has room (its usage is read again first if the last reading is over five minutes old), otherwise down the fallback order, and only to a model whose context window holds the request. Delegated subagents are compacted and retried like other threads. The error now reads "The conversation is too large to hand over to this model's context window…" under a "Context limit reached" title. The **Continuing on** card counts the provider the coordinator runs on as having room, and an old usage reading says it showed room but is out of date.
- Projects that checks and agents made for themselves no longer sit among your own. Acceptance runs, release checks and handoff proofs register real projects to drive the app (October 22's "Run shell acceptance 357" and "swc copy check 2026-10-20"), and they were listed between EasyChamp and specweave. Now the sidebar lists them under a folded **Automated (N)** below your projects. It opens while one of them is open and shows how many threads wait on you. Project pickers offer them after your own, and Overview leaves them and their threads out. A project counts as automated when its creator says so (`origin: "automated"`), when a temporary `auth session issue` token made it, or when its folder is a check's: a temporary folder, a folder inside the app's own data other than its projects folder, or a path with a folder named `scratch`, `verification`, `acceptance` or `*-fixture`. The folder rule is applied each time the project is shown and is never saved, so existing projects are sorted without any change to them. **Move to my projects** and **Move to Automated** in a project's menu save your choice on every machine that has the project, and that choice always wins. A temporary project you move to your projects is no longer deleted when its token ends. Automated projects are not archived, because an archived project refuses new work and the check that owns it may still be running. Agents can mark only their own check's project as automated, and only when they create it; `studio_project_create` explains when a scratch thread is enough. Agents and temporary tokens cannot move a project between the lists. The iPhone app lists automated projects the same way, so the drawer's project list holds only your projects.
- A coordinator or thread stopped on a usage limit now moves to a provider that shows room, not to another one that is out. When Codex hit its weekly limit, the coordinator went to GitHub Copilot because Copilot offers the same model, but Copilot reports no usage and its monthly quota was already spent, so every message came back as "Error: You have exceeded your monthly quota" while Claude Code still had 91% of its week left. A provider that reports no usage (Copilot and the other ACP agents) is now tried only when no provider with a fresh usage read has room; your own fallback order still comes first. Copilot's monthly quota reply now holds that Copilot instance until 00:00 UTC on the 1st of next month instead of 5 hours, or until a later run on it finishes (after you raise the budget, say); another ACP agent's quota reply keeps the 5-hour hold. After a full context, a thread whose project default is Copilot still goes home first. The thread shows "Usage limit reached · Monthly quota used up on this provider." in place of the raw error and request id.
- Threads carry on by themselves after a provider failure, a usage limit or a full context. Before, a provider session that did not open, a usage limit that ran out mid-thread or a context window that overflowed left the thread failed until someone sent another message, and a scheduled run on it kept failing too. Now a session that does not open (including one that hangs for 2 minutes) is retried once its provider reads ready, and a repeat moves the thread to the next ready provider, such as Codex; once Claude's limit resets the thread goes back to Claude, with its queued messages. A provider that answers with its own limit notice instead of doing the work, such as Copilot's "Error: You have exceeded your monthly quota", now counts as a usage limit, so the thread moves on to the next ready provider, other threads and the coordinator keep off that provider, and the thread later goes back to the provider it started on. A full context compacts the conversation and retries the turn. A question the agent asked that you can answer by message no longer stops these recoveries, while an approval still waits for you. Queued messages follow the thread's current provider and model instead of the one that was selected when they were queued. Failure messages now show the innermost cause, such as "registry index request timed out", instead of a generic "could not be opened". Scheduled tasks can run once at a set time; a one-time task that could not run turns itself off and says why.
- A thread on a provider that cannot run here can switch to another one again. When a chat's provider was a managed agent that is not prepared on this Mac (such as Copilot managed after it was removed or never finished installing), its turns failed and the model picker's provider rail greyed out every other provider, OpenAI and Claude included, with "is unavailable in this thread. Start a new thread to switch providers.", so the only way forward was a new chat. The picker now treats a provider that is not installed, turned off, unavailable or in an error state as holding nothing to keep: while nothing is running, every ready provider in the rail can be picked, and the next message continues the conversation there with a handoff summary. A turn that is still running keeps the thread where it is, and a provider that is working normally keeps its usual rules.
- Threads no longer stall when the provider they fall back to cannot start, and a Claude usage limit now resumes at its reset. When Claude Code hit its 5-hour limit, the app moved threads to managed Copilot because it offers the same model, but Copilot's registry had just moved from 1.0.98 to 1.0.101, so every open failed with "Copilot 1.0.101 is not prepared" and the thread sat failed; a scheduled task on such a thread kept firing every 10 minutes. Now managed ACP agents keep running the last prepared version when a newer one is listed (Settings says "Copilot 1.0.98 is running; 1.0.101 is available"), a provider that cannot start (not prepared, not installed, signed out) fails at once without retries, and the limit fallback moves the thread on to the next ready provider, such as Codex, for up to three hops, holding a provider that could not start for 30 minutes. A provider that reports no usage is re-checked before work is sent to it. The thread's run line says "Copilot could not start · continued on Codex". Claude's limit reset is read from the account's usage windows, so a stopped thread resumes at the reset ("Claude's 5-hour limit is used up; it resets at 9:30 AM") instead of waiting for a manual retry, and the denial stays in place while the 5-hour or weekly window is still full. Scheduled tasks skip a fire only when their provider is disabled, signed out or unavailable, or when the thread's last run could not start on it, rather than re-failing every interval.
- The **Continue on another machine** dialog no longer traps you in a choice. Picking **Use the folder as it is** hid the **Files** options, so the dialog stayed on **Continue on** and **Review handoff** with no way back, even after closing and reopening it. The **Files** options now stay visible in every step until a handoff finishes. A review that has not published anything yet has a **Back** button, and changing the file method or the destination there drops the review and returns to the choices; closing the dialog does the same, and the next opening starts from the default **Copy from** method unless a handoff or copy is unfinished. Once a transfer starts publishing commits, the choices stay fixed until that handoff finishes or is recovered, also after a reload. **Choose another folder on a machine** now starts on the remembered machine (else the last handoff target, else the first available one) instead of an empty "Choose a machine", and **Copy to** preselects the same machine.
- A project linked to a copy on another machine no longer says it "Continued from another machine". After **Copy files only** or **Link…**, the coordinator stays where it was, but the project showed the handoff note with "Previous coordinator on <other machine> · Read only" and "History is unavailable", because every linked machine counted as a former coordinator. The note now lists only the machines the coordinator actually came from, by handoff or takeover.
- Requests stay fast on a busy Mac, and the coordinator no longer hangs on "Starting the coordinator". The plan-progress cards read four fields per thread in one query instead of rebuilding every thread, share a folder read between identical requests and refresh at most every 15 seconds while a thread streams; background sweeps share one thread scan for 30 seconds instead of rescanning every 5; settings no longer re-read the secrets files on every read; and reads that cannot finish within 20 seconds answer with an error instead of leaving "Some requests are slow" up. A provider that does not start a turn within 2 minutes now fails that run so the next queued one starts, a queued run held back during an update starts once the update hold ends, and the progress line says "Finishing the previous turn" while a run waits behind another. When the service loses its database lock, the update restarts the service once it is quiet and then installs, instead of refusing until someone restarts it, and the service keeps its database lock if any of its own code closes a database file by another path.
- Another web page can no longer use your sign-in to control the app. A page on another local port (or another site under the same tunnel name) could open the app's live connection with your browser cookie and run threads, or send a plain form post that signed other devices out or issued a socket ticket; a connection or change made with the cookie must now come from the app's own address, the Mac app or an allowed origin, and the same holds for the device and preview streams. Signing a device out now ends its open connections and device streams at once, or within 30 seconds when done from the command line; a browser session also ends them when it expires, while the desktop app and phone, relay and hosted clients, which get new tokens without renewing that session, stay connected; before, an already open window kept working until it reloaded.
- A connection given only file access can no longer reach credentials or the app's own state. File previews, content search, review diffs and file saves took any path on the machine, so such a client could read the saved provider API keys, settings, backups, pairing tokens and terminal logs of this or any other install (including one inside a project folder), read files such as `~/.codex/auth.json`, `~/.ssh`, `~/.npmrc`, Wrangler, Firebase, Terraform, Cargo, Vault or rclone credentials, the tokens of the `gh`, `glab`, `tea` and `forgejo-cli` tools the app drives (also where `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `APPDATA`, `LOCALAPPDATA`, `GH_CONFIG_DIR` or `GLAB_CONFIG_DIR` moves them) (and provider homes moved by settings or `CODEX_HOME`), or write `~/.ssh/authorized_keys`, the common shell start-up files (bash and zsh login and logout files, `~/.config/fish` and `~/.config/environment.d` included), provider config (including `mcp.json`), the service's `launch.sh` and `installation.json`, the release store and updater, provider binaries or the `specwithcode` CLI wrappers; those paths are now refused, also through symlinks, hard links (including to backups, the fleet file, terminal and provider logs, account-profile credentials, and for saves login items, launchers, provider config and binaries, the service runtime and the CLI wrappers), the macOS `/System/Volumes/Data` path, any path under macOS `/.vol` (files named by device and inode), other spellings of a name such as `~/.SSH` or `~/.ſsh`, and a file swapped in between the check and the open (an ordinary replacement such as an editor's save is checked again instead); a path that cannot be resolved is refused rather than let through (on Windows a volume the native lookup fails on, such as a RAM disk or VeraCrypt mount, is resolved with Node's slower lookup first), and so is a save to a path that exists but has no real path. A refused save in the file editor now says "This file is protected from edits inside SpecWithCode. Use another editor to change it." once instead of staying unsaved without a word, and the editor then turns read-only for that file until it is reopened rather than retrying every edit; a refused preview says the same for viewing. When the server's base folder is the home folder, folders such as `~/dev` and `~/backups` stay readable, and a worktree folder set in Settings > Storage inside an app home holds projects, so a repository there named `dev`, `userdata` or `backups` stays usable. Content search no longer reveals whether a protected file matched. Saves can no longer write a file named `.git` or anything inside a `.git` folder (config, hooks, `info/attributes`, `info/exclude`, a linked worktree's `commondir` or `gitdir`), so they cannot make the app's own git commands run a program. The app's git commands run with `core.fsmonitor=false`, so a repository's fsmonitor program never runs; Git's built-in fsmonitor daemon is not used for them either. Review diffs and the Changes totals leave protected files out (both sides of a rename that touches one; a review with hundreds of protected files names the shown files in batches instead of an over-long command line), read old file versions relative to the repository top (a path such as `./settings.json` sent with a subfolder as the project could read a committed protected file), and no longer pass a client-chosen ref to git as an option (without `--end-of-options`, so reviews still work with Git older than 2.30, such as Ubuntu 20.04's 2.25), asset links refuse protected files too, and a refusal names the path as requested, not where a link led. Machine-handoff projects keep working, and attachments, built-in browser downloads, Antigravity's temp folder and its plans, walkthroughs and screenshots, a Codex instance's own session transcripts and memories, other logs, reports agents leave in temp folders and project files still open. Settings > Connections now says that **Network access** uses plain HTTP: traffic is not encrypted and anyone on the same network can capture the sign-in, so use Tailscale HTTPS for remote access.
- Provider API keys and passwords no longer leave the machine they are saved on. The Antigravity (Gemini) API key and the OpenCode server password were sent in full to every app window and paired device that could read settings; they now arrive as a saved marker, and the provider form shows "Stored secret - enter a new value to replace" with a clear button. Saving other provider changes keeps the stored value, a new value replaces it, and clearing still works; moving the OpenCode server URL to another address drops the saved password until you enter it again, so it is never sent to the new server, and the form says why the field is empty. Every text value in the settings of a provider this version does not know, or in a provider setting it does not know (such as one a newer version added), is withheld the same way at any depth, and changing one of them, or the provider's server address (such as the Cursor API endpoint), drops the withheld values rather than keeping them; the ACP Registry icon still shows. Only an address change drops saved values: a new binary or command path, or new environment variables, keeps them. Deleting a Cursor, Codex (ChatGPT sign-in) or Antigravity (Google sign-in) provider instance now also deletes its saved sign-in, again once the provider has shut down so a token it writes while stopping is removed too, and a new instance never starts with a sign-in an earlier instance of the same name left behind, even when it is created again while the old one is still shutting down or failed to stop. If that old sign-in cannot be deleted yet, the new instance starts once it can, retried after 5 seconds, 30 seconds and then every 2 minutes. Editing an instance never deletes its sign-in.
- Automatic updates no longer wait forever on an idle agent. A Mac that keeps a Codex session open between turns sat on an old version with "Waiting for open SpecWithCode terminals and agent processes to close (codex, codex-code-mode-host, node x3, node_repl x4)" although nothing was running; only Update now could get past it. Now, when nothing runs, nothing is queued and no request waits, and the app has stayed that way for the quiet time in the update settings, the update closes those idle Codex processes itself and installs after its usual quiet moment. An open terminal, anything you started in one, or any process the update cannot identify as an idle Codex session still makes it wait, and the update shows which it is waiting for. This takes effect for updates to this version and later.
- Add a machine works again, and a machine added from a `swc-machine-…` line connects. In the desktop app every private-machine button read "Manage access required", because the window signed in to the SpecWithCode service without the access permissions; it now asks for them (see the next entry). Separately, `fleet invite` and Invite this machine made a line whose token could only manage access on that machine, so the main machine could never open a session there: `fleet add` printed "Added" and Settings kept showing Connect machine, failing with "Pairing is unavailable". New lines carry the permissions a connection and Allow workers need (only a sign-in that holds them all can make one), and Add a machine (Settings or `fleet add`) checks the token with that machine first and refuses a line that cannot connect, saying to make a new one there. A machine invited before this release needs this version and a new line. The desktop app's own server no longer runs the Tailscale command to look for a Tailscale HTTPS address set up outside the app, so the App Store Tailscale is not asked for permission because of it.
- You can pair the iPhone app from Settings. Settings > Connections has a **Phone** section with **Pair a phone**: one click makes a one-time code and shows it as a QR code to scan from the app's Pair a machine screen, with the address it holds (the Mac's Tailscale HTTPS name, or its Wi-Fi address with Network access on) and what the phone needs to reach it. Before, the only pairing control sat under Authorized clients, which the desktop window never showed: it signed in to the SpecWithCode service without the access permissions, so Settings said "Manage access required". The desktop now asks for them and signs in again once if a saved sign-in lacks them. The server also lists its Tailscale HTTPS name when Tailscale Serve was set up outside SpecWithCode, so a browser window finds it too, and links no longer point at a hosted web app the build does not have. Network access says why it is off when the service keeps it to this machine. The iPhone app's pairing steps name the new button and it accepts `specwithcode://pair?pairingUrl=` links as well as `?link=`.
- Claude Code's own file tools and four of the app's paths now refuse the app's saved keys and tokens. Claude's Read, Edit, Grep and Glob, in every permission mode including Full access and in `specwithcode triage`, refuse the app's secrets folder (your provider API keys, Codex and GitHub tokens, machine grants), `studio-fleet.json`, the built-in browser's saved sign-ins and Antigravity's Google sign-ins. Antigravity file requests, browser uploads (`preview_upload`, which also refuses folders) and local images in `html_preview`/`html_render` refuse them too, also through links, hard links to the fleet file and other spellings of the same folder. Not covered: shell commands (a command that names the path is refused, but `cd`, wildcards or quoting get past that unless Claude's sandbox is on), Codex turns, threads an agent launches on other providers, and commands the server runs for an agent such as scheduler checks. `settings.json` stays readable and still holds the Antigravity API key and the OpenCode server password in plain text; they are hidden from clients only. This is not encryption; the files are still plaintext on disk, readable by your user account.
- A dropped connection no longer shows up as errors in SpecWithCode, and threads catch up on their own. Before, when the app lost its socket to a machine (even its own, under a stalled server), panels showed a raw "SocketReadError: An error occurred during Read" alert with a Retry that could not help, and a thread could sit on "Syncing messages..." until you reloaded. Now a request whose socket drops waits for the reconnect and loads then; a short catch-up after a reconnect shows no status row at all, and "Syncing messages..." appears only once it lasts past two seconds. A thread whose catch-up failed keeps its messages and says "Messages may be out of date" until it catches up, steady through the app's own retries, and a thread whose server never confirms it caught up subscribes again after 15 seconds, then goes live with what it received.
- SpecWithCode updates no longer fill the disk. Each update copies the app's database (2.5 GB on a long-used Mac) so it can roll back, and nothing removed the old copies: one Mac had 73 of them, 47 GB, until the disk was full and the app froze for seconds at a time, so it showed its own Mac as offline. An update now keeps the newest copy beside the one it makes and deletes older ones; folders you made by hand and anything else in the backups folder stay. A copy cut short by a full disk is removed instead of left behind. When the disk still has too little room for the copy, the update stops before it changes anything, and Settings and the sidebar show that one cause ("Not enough free disk space for the pre-update backup: needs 4.6 GB, 1.2 GB free; SpecWithCode stayed on 1.0.50.") instead of "did not install ... See the update receipt". The service's own output logs, which grew without limit (52 MB on one Mac), now keep their newest 8 MB once they pass 16 MB, and are cut back even when the disk is full. The health watch on the Status page adds a disk check that warns under 5 GB free and reports an outage under 1 GB, naming how much space the database copies take and how many releases are unpacked.
- Builds and releases are harder to tamper with. Every GitHub Action the workflows run is pinned to a full commit SHA, and the Vercel, Cloudflare, release GitHub App and macOS release GitHub tokens reach only the steps that use them. As defence in depth, a release's dependency installs and stage-1 test suites run with the release's GitHub token removed from their environment; that is not isolation: the release script and its build stage still hold the token, a process running as the same user can read it from them, and on a Mac signed in to gh `gh auth token` still returns it. So that those tests never need to fetch, the macOS release checkout is a full clone, and a CI release fetches the older commits the preservation audits read before stage 1 starts. A new Security workflow checks the lockfile for known vulnerabilities, commits for secrets and `.github` for unsafe workflow patterns every day and on every pull request, and its check fails on a pull request that adds one. The check is not required for merging yet (that is a repository setting), and a pull request runs its own copy of the workflow. Security reports now go to anton.abyzov@gmail.com; the address SECURITY.md named before delivered nothing.
- A new release shows in the sidebar within about ten minutes. The app asked the feed once an hour on a timer that stops while the Mac sleeps, so 1.0.43 could sit unseen until you pressed Check for updates. It now checks once the last good check is ten minutes old, looked at every minute by wall clock, so the first minute after a wake catches up; wake, unlock and window focus re-check on the same ten-minute rule. The round update button also shows a downloaded update (restart icon, "Update X downloaded. Click to restart and install.") and a click installs it through the same Restart to update flow, running-work prompt included, instead of checking again.
- SpecWithCode no longer shows its own Mac as offline when the disk is full. Before, a full disk made the app's own server freeze for 2 to 10 seconds at a time, so the window on that same Mac said "Can't reach" its own machine, marked every thread "Host offline", showed a reconnecting banner and a raw read error, and left "Syncing messages..." stuck. Now the app keeps answering its own window on a full or slow disk, and running out of space shows up as one out-of-space line in the logs, then one line when space is back, instead of a stream of repeated errors. A database statement that takes over 250 ms is logged with its SQL text, and a Mac that macOS renamed after a network clash ("MacBook Pro (149)") shows its own name again.
- Shell commands in thread and coordinator replies run where they are. A shell code block (bash, sh, zsh, or an unlabeled block whose lines are commands) has a **Run** button: the command runs on the thread's machine in its working folder, through the same terminal service as the terminal panel, and its output appears under the block with the exit code and a Stop button. On Full access it runs on the click; Supervised and the other modes ask first and name the machine and folder. Nothing runs without a click. A command already run in the thread shows its last output again, and Run again replaces it. An unlabeled command is shown as bash instead of "text", and wrapped commands break only at spaces, so a flag such as `-d` no longer splits across lines. The block's Run used to send the command into the terminal panel; that panel no longer gets a tab per run.
- An unreachable machine's "last seen" no longer gets cut off. The machine picker, the chat banner and Settings > Connections put "last seen 1m ago" before the connection error, which can be a long address, so a truncated line still says when the machine was last there. Your private machines shows both the last-seen time and the reason; before, it showed only one.
- The desktop app's connection to its own server on this Mac rides out a stall instead of giving up. When the local server paused for a few seconds (a full disk, a busy moment), an offline report parked the connection, a Retry click tore down a session that was still working after 3 seconds without an answer, and repeated failures stretched the wait between tries toward five minutes. Now the desktop app's own server is never parked as offline, Retry waits the full 15 seconds for an answer, reconnects come within 3 seconds, and five connected seconds count as stable. Each connect also asks the local server for its details once instead of twice. Remote machines keep the same timing as before, including ones reached through a port forward on this Mac.
- A thread on **Full access** no longer stops for command approvals. Providers take a new permission mode on their next turn, so a turn that started in Supervised kept asking after the thread or its project was raised to Full access (a Codex worker kept asking to run `cat AGENTS.md` under a coordinator showing Full access). The app now approves the command, file and permission requests such a turn still sends, including ones already waiting, on every provider and every kind of thread: coordinators, delegated workers, restored handoffs and threads on other machines. Questions and MCP server requests still come to you. The permission picker next to the coordinator now shows the mode the coordinator actually runs in; before, it showed the saved default, which can differ from existing chats after a global default change.
- **Gemini 4 Argon** is in the Gemini CLI model picker once the agent's models load. Gemini CLI 0.63.0 runs Argon but leaves it out of its catalog, so before this it had to be typed as a custom model. Gemini CLI turns now record their token usage (from the agent's `_meta.quota` report); before, every Gemini CLI turn showed no usage. Provider setup explains how to run Argon on Vertex AI so it bills Google Cloud credits, such as startup credits.
- SpecWithCode no longer calls its own Mac offline. When the app's local server stalls (for example on a full disk), the window used to show the Mac it runs on as a remote machine: "Can't reach <your Mac>" with a raw endpoint timeout, a crossed-out wifi icon on every chat, "Host offline" on thread cards and "Reconnecting to this host. If this does not clear, reload the page." in a project, where reloading gave a blank window. That machine now reads "Catching up…", the chat shows one calm banner, "SpecWithCode on this Mac is busy. Messages send when it catches up.", and nothing suggests a reload; "Connection failed" appears only when the connection has stopped for good. On this Mac, a stall shorter than two seconds shows only "Catching up…", and the busy banner offers no "Continue on" another machine. Remote machines still show when they can't be reached, including this Mac when a phone or another computer opens it over the network, and connection errors now say "Environment endpoint" instead of "Remote environment endpoint".
- Settings > Connections no longer leaves half the window empty. The MCP connections card was its own full-height page stacked on the rest of Connections, so it took half the window however little it showed; it is now a normal section sized to its content, below Your private machines. Machines are a compact list, one line each with the same status the machine picker and sidebar show ("Connected", "Can't reach. Retrying automatically" with last seen) and a Connect machine button on the right; automatic connection and Add a machine are rows in the same card with one-line help. The MCP machine picker and the workers' access picker use the app's grouped dropdown instead of the browser's native select.
- A chat spends fewer lines on chrome. A release may also create the sign-in sessions table on a database that never had one, as long as it holds no session; before, the updater refused that update before it started. A migration may not create a sign-in, pairing, provider or schedule table that already holds rows, change the columns (add, rename, retype), foreign keys or definition of a protected table even when it is empty, or add a trigger that names any of those tables. (#108)
