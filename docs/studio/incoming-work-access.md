# Let another of your machines run work here

In SpecWithCode on the destination machine, open Settings > Machines > Let another of your machines run work here. The card lists the other machines signed in to the same SpecWithCode Connect account, under the names they report, and the machines this app has saved. Each shows what is known about it: online, checking, not answering right now, and its operating system and version when it reported them. A machine that is not answering is listed but cannot be chosen. Choose the machine that will send work, choose the most its work may do, and select Allow [machine]. Read the confirmation before approving: setup gives the sending machine a management key as well as worker access. While no machine may run work here yet, the card is the first thing on the page; afterwards it follows Who can run work here. Not now folds it to one line, remembered on that device, and Show opens it again. When the card has no machine to list it names the one next step: sign in to SpecWithCode Connect, turn on the SpecWithCode Connect switch on this machine, or sign in on the other machine with the same account. For two machines on one Connect account nothing is copied. A machine on another account, or one that cannot reach SpecWithCode Connect, joins with a code or a join line under Another account, or no Connect on the same page; there both machines must be connected with Manage access. Setup requires the installed desktop app. If the sending machine already lists the destination, setup reuses that line and its key, so a retry after a failed grant does not issue another key. It adds the line again only when its saved key cannot work, and then only once per page session.

For example, on M4, choosing M1 sets up M1 → M4. The existing M1 card under M4's Connections page instead controls M4 → M1. A connected app or an update permission does not imply a worker grant in either direction.

The setup uses the existing machine invitation and worker-grant flow. Existing project and sign-in limits remain enforced. If adding the machine succeeds but granting work fails, the page reports partial setup. On the sending machine, open Settings > Machines and choose Allow workers on the destination's card. Existing or revoked incoming grants retain their controls above the setup section.

Signing keys and other secret files still need a separate owner approval for each studio_file_transfer. A worker started by another machine cannot initiate fleet transfers: its coordinator sends the file. Approved project folders and secret-transfer restrictions still apply. Allowing workers does not authorize reading every file on the destination.
