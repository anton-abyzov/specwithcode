# Naming

The product is **SpecWithCode**. Tagline: _The spec travels with the code._

Why the name: every change an agent makes lands with its spec (what was asked, what counts as
done, and the proof) in the same repo as the code, so any agent on any machine can pick it up.

SpecWithCode is built on [SpecWeave](https://spec-weave.com). The open-source CLI and npm
package `specweave` keep their name; SpecWithCode is the workspace that runs agents on top of it.
"Skill Studio" is a different product (the vskill desktop app) and is not part of this rename.

## Rename scope

The rename changed what people read: window titles, the About panel, menus, the Overview
eyebrow, settings copy, CLI help and messages, docs, the README and the marketing pages. It did
not change anything an installed copy, a running service or an update depends on. The three-Mac
fleet, saved connections and encrypted secrets keep working across the upgrade because of that.

Kept on purpose, with the reason:

## Changed in 1.0.0

1.0.0 is the first stable release, and the installed app drops "(Alpha)" from its name.

| What                  | Before (0.1.x and 0.2.x)                     | From 1.0.0                                                                      |
| --------------------- | -------------------------------------------- | ------------------------------------------------------------------------------- |
| Desktop `productName` | `SpecWeave Studio (Alpha)` / `(Nightly)`     | `SpecWithCode` / `SpecWithCode (Nightly)`                                       |
| Installed app         | `/Applications/SpecWeave Studio (Alpha).app` | `/Applications/SpecWithCode.app`                                                |
| Release assets        | `SpecWeave-Studio-<version>-<arch>.<ext>`    | `SpecWithCode-<version>-<arch>.<ext>`, plus `SpecWithCode-<arch>.dmg`           |
| GitHub release flag   | published as pre-releases                    | plain `X.Y.Z` published as Latest (`scripts/studio-projects/release-flags.mjs`) |

An update always installs at the running app's path, so 0.2.x updates to 1.0.0 in place as
`SpecWeave Studio (Alpha).app`. On its first launch 1.0.0 renames its own bundle to
`SpecWithCode.app` and reopens (`apps/desktop/src/updates/macBundleName.ts`). It does this only
for the old name, only where it can write, and only once per version; Launch Services forgets
the old path. When both apps sit side by side after a manual install, SpecWithCode.app moves the
older copy to the Trash. The bundle id, signature, user data folder (`studio-v2`) and Keychain
item do not depend on the file name, so settings, connections, encrypted secrets and macOS
permissions carry over. A Dock tile pinned to the old path has to be pinned again.

Rollback copies of the desktop app are zips under `~/.specweave-studio/backups/desktop.noindex`,
made by `scripts/studio-fleet/desktop_backup.py`. A loose `.app` copy would show up in Spotlight
as another SpecWithCode and could be launched by bundle id. See [releasing](./releasing.md).

## One name in user-facing text

Everything a person reads says SpecWithCode, including the parts that used to carry "Studio":
SpecWithCode Connect, the SpecWithCode home, SpecWithCode mods, SpecWithCode threads, and the MCP
tool descriptions and injected prompts agents read. "Studio" and "SpecWeave Studio" stay only in
the identities in the table above and in code identifiers, file paths, package names, MCP tool
names (`studio_thread_list`, the `studio-code` server), internal log lines and past changelog
entries. "Android Studio", "Mac Studio" and "Skill Studio" are other products.

## Default storage for new installations

All data lives under `~/.specwithcode`: the standalone profile, one folder per managed service identity (`~/.specwithcode/m4`), `backups/`, and `install/` (releases and the update agent, formerly `~/.local/share/specweave-studio`). Every component resolves it through `packages/shared/src/studioIdentity.ts` or `scripts/studio-fleet/studio_paths.py`. An explicit `STUDIO_HOME` still wins. Machines installed before 1.0.35 keep using `~/.specweave-studio` until `scripts/studio-fleet/migrate_home.py --detach` moves it: two same-volume renames, with `~/.specweave-studio` and `~/.local/share/specweave-studio` left as compatibility links so recorded paths keep working. The move stops and restarts the services (a few minutes), keeps launchd labels, the bundle ID and Keychain items, records each step in `~/.specwithcode-migration.json`, can be re-run after an interruption, and `--rollback` restores the old layout. It never runs automatically during an update.
